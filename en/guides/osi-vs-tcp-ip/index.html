OSI Model vs TCP/IP Model Explained (With Examples)

The Routerel team· Updated: November 5, 2026· 12 min read

Layered models are the first thing you learn in networking and the last thing you stop using for troubleshooting, even after years on the job. "It's a Layer 1 problem" means "check the cable"; "ping works but the website doesn't" points you to the upper layers. The model is a shared language.

In this guide you'll see the 7 layers of the OSI model and the 4 layers of the TCP/IP model, what the data is called at each layer, which protocols and devices belong to each one, how a request to a website is encapsulated step by step, and which traps show up in the exam. At the end there are 5 practice questions with answers.

In the Networking Academy CCNA v8 courses, the models are taught in CCNA 1 · ITN, module 2 (protocols and models), and the layers are then covered one by one: physical (module 3), data link (module 5), network (module 9), transport (module 14) and application (module 15).

Why we use layered models

A network does many things at once: it turns bits into signals, finds the recipient on the same segment, picks a path across the Internet, checks that all the data arrived and hands it to the right application. Layered models split that work into pieces, each with its own role:

  • each layer does one kind of job and uses the services of the layer below it;
  • vendors can work independently: one company's network card works with another company's operating system, because both follow the same interfaces between layers;
  • you can change one layer without touching the others: you switch from cable to Wi-Fi and the browser doesn't notice a thing;
  • you troubleshoot methodically: you check the layers one at a time, bottom-up or top-down.

The OSI model: the 7 layers

OSI (Open Systems Interconnection) was published by ISO as a reference model. The actual OSI protocols never caught on, but the 7-layer split became the standard vocabulary of the profession.

swipe

No. Layer What it does, in short PDU Example protocols and technologies Typical devices
7 Application provides network services to applications data HTTP, HTTPS, DNS, DHCP, SMTP, IMAP, FTP, SSH, SNMP hosts, servers
6 Presentation data format: encoding, compression, encryption data ASCII, UTF-8, JPEG, MPEG hosts
5 Session opens, maintains and closes the dialog between applications data session management, checkpoints for resuming hosts
4 Transport process-to-process delivery, ports, reliability segment (TCP) / datagram (UDP) TCP, UDP hosts, firewalls
3 Network logical addressing and path selection between networks packet IPv4, IPv6, ICMP, ICMPv6, OSPF router, Layer 3 switch
2 Data Link delivery on the same segment, MAC addresses, error detection frame Ethernet, Wi-Fi (802.11), PPP switch, bridge, access point, network card
1 Physical transmits bits as electrical, optical or radio signals bits UTP cable, fiber, radio, RJ-45 connectors hub, repeater, cables, connectors

A few clarifications that save you from confusion:

  • Layer 2 actually has two sublayers: LLC (the link to the network layer) and MAC (media access and physical addressing).
  • Ethernet and Wi-Fi cover both Layer 1 and Layer 2. The standard describes both the signals and the frame format.
  • At Layer 4, if the question doesn't name the protocol, the expected PDU is segment.
  • A network card works at Layers 1 and 2, while a computer or server uses all 7.
  • A modern firewall can inspect traffic from Layer 3 all the way up to Layer 7, depending on the type.

The upper layers (5, 6, 7): why they feel fuzzy

In practice, applications do the work of Layers 5 and 6 themselves. A browser opens the session, picks the data format and encrypts the connection (with TLS), all inside the same program. That's why many people treat them together as "the application part", which is exactly what the TCP/IP model does.

The TCP/IP model: 4 layers (or 5)

The TCP/IP model came about together with the protocols the Internet uses. It isn't a theory written up front; it describes how today's networks actually work. In CCNA materials it has 4 layers:

swipe

TCP/IP layer Maps to OSI What you find here
Application 5, 6, 7 HTTP, DNS, DHCP, SMTP, SSH, FTP
Transport 4 TCP, UDP
Internet 3 IPv4, IPv6, ICMP
Network Access 1, 2 Ethernet, Wi-Fi, cabling, signals

Some books show a 5-layer TCP/IP model, where Network Access is split into Data Link and Physical. Same idea, just with a clearer bottom boundary. In the exam, read carefully how many layers the model in the question has.

OSI vs TCP/IP side by side

swipe

Criterion OSI TCP/IP
Number of layers 7 4 (or 5, in the extended version)
Type reference model protocol model, actually in use
Upper layers Application, Presentation, Session kept separate all in Application
Layer 3 is called Network Internet
Lower layers Data Link and Physical kept separate Network Access (or Link)
What you use it for vocabulary, troubleshooting, classifying devices understanding how data moves across the Internet

In short: when you say "Layer 2 switch" or "Layer 1 problem", you're speaking OSI. When you explain how a web page gets from the Internet to your phone, you're thinking in TCP/IP. The two overlap neatly, and in the exam you need to switch between them effortlessly.

PDUs: what the data is called at each layer

On the way down, each layer adds its own header in front of the data it gets from above. The result is called a PDU (Protocol Data Unit), and it has a different name at each layer:

swipe

Layer PDU What the layer adds
Application data the actual content, for example the HTTP request
Transport segment (TCP) or datagram (UDP) source and destination ports, plus sequence numbers for TCP
Network / Internet packet source and destination IP addresses, TTL
Data Link frame source and destination MAC addresses, type, plus a trailer with the FCS
Physical bits adds no header, turns the frame into signals

Layer 2 is the only one that also adds something at the end: the FCS (Frame Check Sequence), a checksum the receiver uses to verify that the bits arrived intact. A frame with a bad FCS is dropped.

Adding headers is called encapsulation. The reverse process at the receiver, where each layer reads and removes its own header, is called decapsulation.

Full example: what happens when you open a website

Let's follow a real request. You're on a laptop, connected to your home router, and you type routerel.app into the browser. The starting data (made up, but realistic):

swipe

What Value
The laptop IP 192.168.1.10/24, MAC AA-AA-AA-11-11-11
The home router (default gateway) IP 192.168.1.1, MAC BB-BB-BB-22-22-22
The website's server IP 203.0.113.10 (a documentation address)

Step 0: find the server's IP address (DNS)

The browser knows a name, but the network works with addresses. The laptop asks a DNS server, usually over UDP port 53, and gets back the address 203.0.113.10. The DNS request also goes through every layer, exactly as below, just with UDP instead of TCP.

Step 1: the application layer

The browser prepares the HTTP request (essentially "give me the home page of routerel.app"). Because the site uses HTTPS, once the TCP connection is established the request is encrypted with TLS. As far as the model is concerned, the result is data.

Step 2: the transport layer

HTTPS uses TCP port 443. Before any data is sent, TCP sets up the connection with the three-way handshake (SYN, SYN-ACK, ACK). Then the data gets a TCP header with:

  • source port: a number picked temporarily by the operating system, for example 51514, so the reply gets back to the right browser connection;
  • destination port: 443;
  • sequence and acknowledgment numbers, so nothing gets lost and everything arrives in order.

Now you have a segment.

Step 3: the network layer

The segment gets an IP header: source 192.168.1.10, destination 203.0.113.10, a TTL (for example 64 or 128, depending on the operating system) and the field saying there's TCP inside. Now you have a packet.

Step 4: the data link layer

Here's the most important idea in the whole example. The laptop compares the destination's network with its own: 203.0.113.10 is not in 192.168.1.0/24. So the packet can't be delivered directly; it has to be handed to the default gateway.

The laptop needs the router's MAC address, not the server's. If it doesn't already have it cached, it finds it with ARP. Then it builds the Ethernet frame:

  • destination MAC: BB-BB-BB-22-22-22 (the home router);
  • source MAC: AA-AA-AA-11-11-11 (the laptop);
  • type: IPv4;
  • at the end, the FCS.

Now you have a frame.

Step 5: the physical layer

The network card turns the frame into bits: electrical signals on the cable or radio waves on Wi-Fi.

What the router does

The router receives the bits and rebuilds the frame. It checks the FCS, sees that the destination MAC is its own and strips the frame. It reads the IP packet, looks up the destination in its routing table, decrements the TTL by 1 and builds a new frame with the right MAC addresses for the next link. The home router does one more thing: NAT, replacing the private source IP address with the public address it got from the ISP.

Every router along the path repeats the story: a new frame at every hop, while the IP packet travels on.

What the server does

The server does the reverse trip: bits → frame (checks the FCS, strips the Ethernet header) → packet (checks the destination IP, strips the IP header) → segment (sees port 443 and hands the data to the web server) → data. The web server replies, and the reply is encapsulated and sent back with the ports swapped: source 443, destination 51514.

Header summary

swipe

On the link Source → destination MAC Source → destination IP Ports
laptop → home router laptop → router 192.168.1.10 → 203.0.113.10 51514 → 443
home router → ISP router → next router public IP → 203.0.113.10 (after NAT) NAT may change the source port, destination stays 443
last router → server router → server public IP → 203.0.113.10 → 443

The rule to remember: MAC addresses change at every hop, IP addresses stay the same end to end (unless NAT steps in).

Common exam traps

  1. The switch is Layer 2, the router Layer 3, the hub Layer 1. The exception: the multilayer (Layer 3) switch, which can route.
  2. Segment vs. datagram vs. packet vs. frame. TCP makes segments, UDP datagrams, IP packets, Ethernet frames. If the question says "at Layer 2", the answer is frame. If the question doesn't name the protocol, the expected layer 4 PDU is segment.
  3. Who adds which address. Ports: Layer 4. IP addresses: Layer 3. MAC addresses: Layer 2.
  4. Only Layer 2 adds a trailer. Layers 4, 3 and 2 add headers; only Layer 2 adds a trailer (FCS).
  5. Internet = Network. The "Internet" layer in TCP/IP maps to OSI Layer 3, not to the Internet as a whole.
  6. Network Access = Layers 1 and 2. Not just Layer 1.
  7. Encryption, compression and formats (JPEG, ASCII) belong to Layer 6, Presentation. The dialog (opening, closing, resuming) belongs to Layer 5, Session.
  8. ICMP is at Layer 3, even though its messages travel inside IP packets. Ping doesn't use ports.
  9. ARP sits on the boundary between Layers 2 and 3. It maps an IP address to a MAC address, and its messages go straight into Ethernet frames, with no IP header. Read carefully what the question is asking: its role, or where its messages are carried.
  10. The destination MAC of a packet headed for the Internet is the gateway's, not the server's. This is probably the most common trap in the whole topic.
  11. Encapsulation goes top-down (7 → 1), decapsulation bottom-up (1 → 7).

Practice questions

  1. A PC sends an email. At which OSI layer is the destination port added, and what is the resulting PDU called if the transport protocol is TCP?
  2. A switch receives a frame and looks in its address table to decide which port to send it out of. Which address does it decide on, and at which layer is it working in this case?
  3. A packet leaves PC A, passes through two routers and reaches server B. Without NAT, what changes at each hop: the MAC addresses, the IP addresses or both?
  4. Which OSI layers does the Network Access layer of the TCP/IP model map to?
  5. A file is compressed and encrypted before it's sent. Which OSI layer does the model assign these functions to?
Answers

1. At Layer 4 (Transport). With TCP, the PDU is called a segment. (With UDP it would have been a datagram.)

2. On the destination MAC address, at Layer 2 (Data Link). A regular switch doesn't look at IP addresses when it switches frames.

3. Only the MAC addresses change. Each router strips the old frame and builds a new one for the next link, but the source and destination IP addresses stay the same from A to B. (The TTL also changes, dropping by 1 at each router.)

4. Layers 1 (Physical) and 2 (Data Link).

5. Layer 6 (Presentation), which handles the format, compression and encryption of data.

How to use the model in practice

The model isn't just for the exam. When "the internet doesn't work", an orderly bottom-up troubleshooting pass looks like this:

  • Layer 1: is the cable plugged in, is the port LED on, is Wi-Fi turned on?
  • Layer 2: is the port in the right VLAN, does the MAC address show up in the switch's table? (For VLANs, see the guide to VLANs and trunks.)
  • Layer 3: does the device have the right IP address, mask and gateway? Does ping to the gateway work? (For masks and subnets: subnetting step by step; for IPv6: IPv6 addresses explained.)
  • Layer 4 and above: does ping to the server work but the website doesn't? Then check DNS, the port, the firewall, the application.

The commands you use for these checks on Cisco devices are collected in the Cisco IOS commands cheat sheet.

Frequently asked questions

What are the 7 layers of the OSI model?

From the bottom up: 1 Physical, 2 Data Link, 3 Network, 4 Transport, 5 Session, 6 Presentation and 7 Application.

What is the difference between the OSI model and the TCP/IP model?

OSI is a 7-layer reference model used to describe and troubleshoot networks. TCP/IP is the model the Internet actually runs on, and it has 4 layers: Application, Transport, Internet and Network Access. OSI layers 5, 6 and 7 are merged into Application, and layers 1 and 2 into Network Access.

What is a PDU?

A PDU (Protocol Data Unit) is the name for the data at a given layer, together with that layer's header: data at the application layer, a segment (TCP) or datagram (UDP) at the transport layer, a packet at the network layer, a frame at the data link layer and bits at the physical layer. If the question doesn't name the protocol, the expected layer 4 PDU is segment.

Which layer does a switch work at, and which layer does a router work at?

A regular switch works at Layer 2 and makes decisions based on MAC addresses. A router works at Layer 3 and makes decisions based on IP addresses. A multilayer (Layer 3) switch can also route.

What changes when a packet passes through a router?

The router strips the frame, reads the IP packet, decrements the TTL and builds a new frame for the next link. MAC addresses change at every hop, while IP addresses stay the same end to end, unless NAT is performed along the way.

How often does the OSI model come up in the CCNA exam?

Rarely as a pure memorization question, but very often indirectly: layer vocabulary shows up in troubleshooting, devices, protocols and the explanations of many questions. It's worth knowing it really well from the start. For the exam in general, see our guide to CCNA.
