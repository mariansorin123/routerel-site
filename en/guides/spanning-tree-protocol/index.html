Spanning Tree Protocol Explained: STP, RSTP and Rapid PVST+

The Routerel team· Updated: November 9, 2026· 14 min read

Connect two switches with two cables and you'd expect a more reliable network. Without Spanning Tree, you get the opposite: within seconds the switches are drowning in copies of their own broadcasts.

This guide covers why Layer 2 loops happen, how the root bridge and port roles are chosen, what RSTP and Rapid PVST+ add, what PortFast and BPDU Guard are for, and how to configure and verify it all in Cisco IOS. Then we solve a four-switch topology step by step, and you finish with exercises and answers.

In the Networking Academy CCNA v8 courses, Spanning Tree is in CCNA 2 · IEN, module 6. Rapid PVST+ builds a separate tree per VLAN, so if VLANs and trunks still feel shaky, read the VLANs and trunks guide first.

Why Layer 2 loops are so dangerous

An IP packet carries a TTL field. Every router decrements it, and when it hits zero the packet is dropped. An Ethernet frame has no such field. Once a frame is caught in a loop of switches, nothing ever removes it.

Picture three switches cabled in a triangle, with no STP. A PC sends an ARP request, which is a broadcast:

  1. SW1 floods it out every other port, so a copy goes to SW2 and another to SW3.
  2. SW2 forwards its copy to SW3, and SW3 forwards its copy to SW2.
  3. Both copies come back to SW1, which floods them again.

Three problems show up at once:

  • Broadcast storm. The copies multiply, links saturate, switch CPUs spike, and hosts spend all their time processing broadcasts.
  • MAC address table instability. SW1 sees the same source MAC arriving on the PC's port, then on the port toward SW2, then on the port toward SW3. It rewrites the entry many times a second and sends unicast traffic the wrong way.
  • Duplicate frames. A unicast frame to a destination the switches haven't learned yet gets flooded, and the destination receives several copies.

Removing the redundant links isn't an option, because a single cable is a single point of failure. Spanning Tree Protocol (IEEE 802.1D) keeps the cables but logically blocks just enough ports to leave a loop-free tree. When an active link fails, it brings a blocked one back into service.

The bridge ID and the root bridge election

Switches running STP exchange BPDUs (Bridge Protocol Data Units). From them, each switch learns who the root is, how far away it is and who is sending.

Step one is electing the root bridge, the switch the whole tree hangs from. The switch with the lowest bridge ID (BID) wins. The BID is 8 bytes long:

swipe

Part Size Contents
Priority 4 bits configurable, in multiples of 4096 (0–61440); 32768 by default
Extended system ID 12 bits the VLAN number
MAC address 48 bits the switch's MAC address

IOS shows the first two parts together as one 16-bit number. That's why a switch with default settings shows a priority of 32778 in VLAN 10 (32768 + 10) and 32769 in VLAN 1.

Why multiples of 4096? Because the VLAN number takes up the lower 12 bits of that 16-bit field. Only the top 4 bits are left for the priority, and those bits are worth 4096, 8192, 16384 and 32768. Drop 32778 into the binary converter and you'll see the split.

Two BIDs are compared like this:

  1. priority (including the VLAN number): lower wins;
  2. if that's a tie, MAC address: lower wins.

At startup, every switch assumes it is the root and sends BPDUs with its own BID as the root ID. As soon as it hears a BPDU with a better (lower) root ID, it stops claiming and starts relaying that root instead. A few seconds later everyone agrees.

The catch: leave everything at defaults and the root becomes whichever switch has the lowest MAC address. That's often the oldest switch in the building, possibly an access switch in a wiring closet. So you always choose the root yourself, using priority.

Port cost and root path cost

Every port has a cost that goes down as speed goes up. For CCNA you work with the short method (from 802.1D-1998), the default on many Catalyst switches, including the 2960 series:

swipe

Speed Short cost Long cost
10 Mbps 100 2,000,000
100 Mbps 19 200,000
1 Gbps 4 20,000
10 Gbps 2 2,000

The long method (802.1t) exists because the short values run out of room at higher speeds. You enable it with spanning-tree pathcost method long, on every switch, so the numbers stay comparable.

Root path cost is the total cost of the path to the root. The root advertises a cost of 0. Each switch that receives a BPDU adds the cost of the port it received it on, then advertises the new total downstream. What counts is the cost of the ports facing the root (where the BPDUs arrive), not the ports the BPDU is sent out of.

Example: the root connects to SW2 over Gigabit, and SW2 connects to SW4 over Fast Ethernet. SW2's root path cost is 4, and SW4's is 4 + 19 = 23.

Root ports, designated ports and blocked ports

Once the root is known, every port gets a role. Work them out in the same order every time.

1. Root port: one per non-root switch

Every switch except the root picks exactly one root port: the port with the best path to the root. The tie-breakers, in order:

  1. lowest root path cost;
  2. lowest sender bridge ID (the neighbor that sent the BPDU);
  3. lowest sender port priority (128 by default);
  4. lowest sender port number.

Note that the last two look at the neighbor's port, not your own. They only matter when two switches are connected by more than one cable. Exercise 3 shows how this trips people up.

The root bridge has no root port. It is the destination.

2. Designated port: one per segment

Every link (segment) gets exactly one designated port: the port on the switch that offers that segment the best path to the root. The tie-breakers:

  1. lowest root path cost of the switch;
  2. lowest bridge ID;
  3. lowest port ID (priority, then number).

All of the root bridge's ports are designated, since its root path cost is 0. Ports facing end devices are designated too.

3. Everything else: blocked

Any port that is neither a root port nor a designated port is blocked. It doesn't forward or receive user frames, but it keeps listening to BPDUs so it can take over if the topology changes.

A quick sanity check: on any link between two switches, one end is always designated. The other end is either a root port or blocked. Both ends blocked on the same link can't happen.

Port states: 802.1D vs RSTP

Classic STP (802.1D) moves a port through five states:

swipe

802.1D state Forwards frames? Learns MACs? Typical time
Blocking no no up to 20 s (max age)
Listening no no 15 s (forward delay)
Learning no yes 15 s (forward delay)
Forwarding yes yes normal operation
Disabled no no administratively down

The default timers are hello 2 s, max age 20 s and forward delay 15 s. If a switch loses its root port because of an indirect failure (a link further away goes down), the backup port waits out max age, then goes through listening and learning: 20 + 15 + 15 = 50 seconds with no traffic. Plugging in a new link takes 30 seconds (listening plus learning).

RSTP (Rapid Spanning Tree, 802.1w, later folded into 802.1D-2004) keeps the same election rules but cuts convergence to a few seconds. It has just three states:

swipe

RSTP state 802.1D equivalent Forwards frames? Learns MACs?
Discarding disabled, blocking, listening no no
Learning learning no yes
Forwarding forwarding yes yes

It also separates port roles from port states:

swipe

RSTP role Meaning State
Root best path to the root forwarding
Designated best port for a segment forwarding
Alternate backup path to the root through another switch; takes over immediately if the root port fails discarding
Backup backup port to a segment where the same switch already has a designated port (only on shared media, such as a hub) discarding
Disabled port is down discarding

Where the speed comes from:

  • the alternate port is calculated in advance, so when the root port fails it becomes the new root port almost immediately;
  • neighbors on point-to-point (full-duplex) links negotiate directly with a proposal/agreement handshake instead of waiting for timers;
  • every switch sends its own BPDUs every 2 seconds, and a neighbor is declared lost after 3 missed hellos (6 s) rather than 20 s;
  • edge ports (host ports configured with PortFast) go straight to forwarding.

PVST+ and Rapid PVST+

The original standard built one tree for the whole network, no matter how many VLANs you had. Cisco's variants run a separate instance per VLAN:

swipe

Mode Algorithm Instances Command
PVST+ 802.1D one per VLAN spanning-tree mode pvst
Rapid PVST+ RSTP (802.1w) one per VLAN spanning-tree mode rapid-pvst
MST 802.1s groups of VLANs spanning-tree mode mst

On a 2960 the default is PVST+; some newer models ship with Rapid PVST+ already on. Check with show spanning-tree summary. For CCNA, the mode that matters is Rapid PVST+.

The big win of per-VLAN instances is load sharing. With two distribution switches, D1 and D2, you make D1 the root for VLAN 10 and D2 the root for VLAN 20. The link that's blocked for VLAN 10 carries VLAN 20 traffic and vice versa, so both uplinks do useful work.

PortFast, BPDU Guard, Root Guard and Loop Guard

These features protect the edge of the switched network. In short:

PortFast puts an access port straight into forwarding, skipping the wait. Use it on ports facing PCs, printers and servers, so a host doesn't sit for 30 seconds before it can get a DHCP lease. In RSTP terms, a PortFast port is an edge port. Don't enable it on ports toward other switches; IOS prints a warning saying exactly that when you turn it on.

BPDU Guard shuts the port down if a BPDU arrives. The port goes err-disabled and passes nothing. A user port should never see a BPDU, so if one shows up, someone has plugged in a switch. The log looks like this:

%SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port FastEthernet0/5 with BPDU Guard enabled. Disabling port.
%PM-4-ERR_DISABLE: bpduguard error detected on Fa0/5, putting Fa0/5 in err-disable state

After removing the rogue switch, you bring the port back with shutdown followed by no shutdown, or automatically with errdisable recovery cause bpduguard.

Root Guard goes on designated ports where a better root should never appear, typically distribution ports facing access switches. If a superior BPDU arrives on such a port, the port is placed in the root-inconsistent state (blocked). Unlike BPDU Guard, it recovers on its own once the superior BPDUs stop.

Loop Guard goes on root and alternate ports. If such a port stops receiving BPDUs (a fiber that only works in one direction, for example), Loop Guard keeps it from turning designated and opening a loop, holding it in the loop-inconsistent state instead.

Configuration

Mode and root bridge

D1(config)# spanning-tree mode rapid-pvst
D1(config)# spanning-tree vlan 10 root primary
D1(config)# spanning-tree vlan 20 root secondary

root primary is a macro, not a permanent setting. When you enter it, the switch looks at the current root and sets its own priority to 24576 if that's enough to win. If the current root already has a lower priority, it sets a priority 4096 below that. Only the result is saved in the running config, for example spanning-tree vlan 10 priority 24576. If someone later lowers another switch's priority, the macro doesn't re-run.

root secondary sets the priority to 28672: lower than the default 32768, so this switch takes over as root if the primary fails.

Many admins prefer setting the value explicitly, because it's predictable:

D1(config)# spanning-tree vlan 10 priority 4096
D2(config)# spanning-tree vlan 10 priority 8192

A value that isn't a multiple of 4096 is rejected, and IOS lists the accepted values.

For load sharing, swap the roles on the second switch:

D2(config)# spanning-tree vlan 20 root primary
D2(config)# spanning-tree vlan 10 root secondary

Port cost and port priority

To influence which port becomes the root port, change the cost (on the local switch) or the port priority (which the neighbor uses as a tie-breaker):

SW4(config)# interface FastEthernet0/2
SW4(config-if)# spanning-tree vlan 10 cost 10
SW4(config-if)# exit
D1(config)# interface GigabitEthernet0/1
D1(config-if)# spanning-tree vlan 10 port-priority 64

Port priority ranges from 0 to 240 in steps of 16, with 128 as the default.

Edge protection

SW4(config)# interface range FastEthernet0/3 - 24
SW4(config-if-range)# switchport mode access
SW4(config-if-range)# spanning-tree portfast
SW4(config-if-range)# spanning-tree bpduguard enable
SW4(config-if-range)# exit
D1(config)# interface GigabitEthernet0/2
D1(config-if)# spanning-tree guard root

The global versions:

SW4(config)# spanning-tree portfast default
SW4(config)# spanning-tree portfast bpduguard default

The first enables PortFast on every access port. The second enables BPDU Guard on every PortFast port. On some IOS releases (for example 15.2E on a Catalyst 2960-X) these commands include the keyword edge (spanning-tree portfast edge, spanning-tree portfast edge default, spanning-tree portfast edge bpduguard default), but they do the same job. Catalyst 9000 switches running IOS XE use the plain forms shown above.

Verification

swipe

Command What it shows
show spanning-tree every VLAN: the root, the local BID, and each port's role, state and cost
show spanning-tree vlan 10 the same, for VLAN 10 only
show spanning-tree summary the mode (pvst or rapid-pvst), the VLANs this switch is root for, global PortFast and BPDU Guard settings
show spanning-tree interface Fa0/1 detail per-port details: BPDUs sent and received, PortFast, BPDU Guard
show spanning-tree inconsistentports ports blocked by Root Guard or Loop Guard
show interfaces status err-disabled ports shut down, for example by BPDU Guard

Reading the port table in show spanning-tree: Role is Root, Desg, Altn or Back; Sts is FWD, BLK, LRN or LIS. Under Rapid PVST+, IOS still shows discarding ports as BLK. Type shows P2p (full duplex), Shr (half duplex, shared) and Edge for PortFast ports.

Worked example: four switches

Four 2960 switches carry VLAN 10 and run Rapid PVST+. SW1 has spanning-tree vlan 10 root primary configured; the others are at default priority.

swipe

Link One end Other end Speed (cost)
SW1 – SW2 SW1 Gi0/1 SW2 Gi0/1 1 Gbps (4)
SW1 – SW3 SW1 Gi0/2 SW3 Gi0/1 1 Gbps (4)
SW2 – SW3 SW2 Gi0/2 SW3 Gi0/2 1 Gbps (4)
SW2 – SW4 SW2 Fa0/24 SW4 Fa0/1 100 Mbps (19)
SW3 – SW4 SW3 Fa0/24 SW4 Fa0/2 100 Mbps (19)

swipe

Switch Priority shown MAC address
SW1 24586 0050.0f00.9000
SW2 32778 0050.0f00.2000
SW3 32778 0050.0f00.3000
SW4 32778 0050.0f00.1000

Try it yourself before reading on.

Step 1: the root bridge

SW1's priority of 24586 beats 32778, so SW1 is the root. SW4 has the lowest MAC address, but that's irrelevant: MAC only breaks ties between equal priorities. Both of SW1's ports (Gi0/1 and Gi0/2) are designated.

Step 2: root ports

SW2. Directly via Gi0/1: cost 4. Via SW3: 4 + 4 = 8. Via SW4 and then SW3: 4 + 19 + 19 = 42. Root port: Gi0/1 (cost 4).

SW3. Directly via Gi0/1: cost 4. Root port: Gi0/1.

SW4. Via Fa0/1 (toward SW2): 4 + 19 = 23. Via Fa0/2 (toward SW3): 4 + 19 = 23. A tie. Next comes the sender's BID: SW2 (32778, 0050.0f00.2000) versus SW3 (32778, 0050.0f00.3000). Priorities are equal, so the MAC decides, and SW2's is lower. Root port: Fa0/1.

Step 3: designated ports

swipe

Link Root path cost Designated port Other end
SW1 – SW2 0 vs 4 SW1 Gi0/1 SW2 Gi0/1: root port
SW1 – SW3 0 vs 4 SW1 Gi0/2 SW3 Gi0/1: root port
SW2 – SW3 4 vs 4: tie, lower BID wins (SW2) SW2 Gi0/2 SW3 Gi0/2: blocked (alternate)
SW2 – SW4 4 vs 23 SW2 Fa0/24 SW4 Fa0/1: root port
SW3 – SW4 4 vs 23 SW3 Fa0/24 SW4 Fa0/2: blocked (alternate)

Exercises

  1. A switch has spanning-tree vlan 30 priority 28672 configured. What priority does show spanning-tree vlan 30 display?
  2. Three switches, same VLAN: SWA (24577, 00a0.c911.0005), SWB (24577, 00a0.c911.0002), SWC (4097, 00a0.c911.0009). Which one is the root? Which VLAN is this?
  3. SWX connects directly to the root with two crossed Gigabit cables: SWX Gi0/1 goes to the root's Gi0/2, and SWX Gi0/2 goes to the root's Gi0/1. All port priorities are 128. Which SWX port becomes the root port?
  4. In the worked example, the SW1 – SW2 link fails. What are the new root ports on SW2 and SW4, and which port ends up blocked?
  5. You want D1 to be root for VLAN 10 and backup root for VLAN 20, and D2 the other way round. Write the commands.
Answers

1. 28672 + 30 = 28702.

2. SWC. Priority is compared first, and 4097 is lower than 24577, so the MAC addresses never come into play. The priorities are 4096 + 1 and 24576 + 1, so this is VLAN 1.

3. Gi0/2. Cost is equal (4 on both), the sender BID is the same (it's the same switch), and the sender port priorities are equal. The deciding factor is the sender's port number: SWX Gi0/2 receives BPDUs from the root's Gi0/1, which has the lower number. The local port number doesn't matter.

4. SW2: via Gi0/2 (toward SW3) the cost is 4 + 4 = 8, while via Fa0/24 (toward SW4) it would be much higher, so the root port is Gi0/2. SW4: via Fa0/2 (toward SW3) it's 4 + 19 = 23, via Fa0/1 (toward SW2) it's 8 + 19 = 27, so the root port is Fa0/2. On the SW2 – SW4 link, SW2 has cost 8 and SW4 has 23, so SW2 Fa0/24 is designated and SW4 Fa0/1 becomes alternate (blocked). SW3 Gi0/2 becomes designated (4 vs 8). Three links stay active: SW1 – SW3, SW3 – SW2 and SW3 – SW4.

5.

D1(config)# spanning-tree vlan 10 root primary
D1(config)# spanning-tree vlan 20 root secondary
D2(config)# spanning-tree vlan 20 root primary
D2(config)# spanning-tree vlan 10 root secondary

Or explicitly, with spanning-tree vlan 10 priority 24576 on D1 and spanning-tree vlan 10 priority 28672 on D2 (and the reverse for VLAN 20).

The fastest way to learn this

  • Solve topologies on paper first, always in the same order: root bridge, root ports, designated ports, everything else blocked. Only then confirm in a simulator with show spanning-tree.
  • Memorize the four short costs: 100, 19, 4, 2. For where STP fits in the exam, see our guide to CCNA.
  • Connect STP to VLANs: with Rapid PVST+, every VLAN has its own tree. Review trunking in the VLANs and trunks guide and the basics in the Cisco IOS commands cheat sheet.

Frequently asked questions

What does Spanning Tree Protocol do?

It prevents Layer 2 loops in a network with redundant links between switches. STP elects a central switch (the root bridge), works out each switch's best path to it and blocks the ports that would close a loop. If an active link fails, it unblocks a backup port.

How is the root bridge elected?

The switch with the lowest bridge ID wins. Priority is compared first (32768 plus the VLAN number by default); if priorities are equal, the lowest MAC address wins.

What is the difference between STP and RSTP?

RSTP (802.1w) builds the same tree as STP (802.1D) but converges in a few seconds instead of 30 to 50 seconds. It has only three port states (discarding, learning, forwarding), new roles for backup ports (alternate and backup) and moves host-facing ports straight to forwarding.

What is the difference between PVST+ and Rapid PVST+?

Both are Cisco variants with one spanning tree instance per VLAN. PVST+ uses the classic 802.1D algorithm, while Rapid PVST+ uses RSTP and converges much faster. You select them with spanning-tree mode pvst or spanning-tree mode rapid-pvst.

Why can bridge priority only be set in multiples of 4096?

The priority field is 16 bits, but the last 12 bits hold the extended system ID, which is the VLAN number. Only the top 4 bits are left for the priority, and their values are multiples of 4096, from 0 to 61440.

What does BPDU Guard do?

It shuts the port down (err-disabled) as soon as a BPDU arrives. It's used on PortFast ports, where only end devices belong, so a wrongly connected switch can't change the topology or create a loop.
