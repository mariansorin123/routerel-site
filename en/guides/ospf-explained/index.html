OSPF Explained: Single-Area OSPFv2 Configuration and Troubleshooting

The Routerel team· Updated: November 9, 2026· 16 min read

OSPF is the dynamic routing protocol you'll configure most often for the CCNA. The idea is simple: routers tell each other what links they have, each builds a map of the network and picks the shortest path on its own. The details (router ID, neighbor states, DR/BDR, cost, network types) are what break labs and show up on the exam.

Here you build a four-router OSPF network from scratch: neighbors, the DR/BDR election, cost, two ways to configure OSPF, passive interfaces, the default route, the show commands and the usual faults. Exercises with answers are at the end.

In the Networking Academy CCNA v8 courses, OSPF is in CCNA 3 · CEN, modules 3 (OSPF Fundamentals) and 4 (OSPF Tuning).

OSPF in a nutshell

OSPF (Open Shortest Path First) is a link-state routing protocol and an open standard. The IPv4 version is OSPFv2; IPv6 uses OSPFv3.

What it does, in three steps:

  1. Each router discovers neighbors on its interfaces using Hello packets.
  2. Neighbors exchange descriptions of their links, called LSAs (Link-State Advertisements). Every router in the same area ends up with an identical database, the LSDB.
  3. Each router runs the SPF (Dijkstra) algorithm over the LSDB and installs the cheapest path to every network in its routing table.

Numbers worth memorizing:

swipe

Item Value
Administrative distance 110
Metric cost (the sum of the outgoing interface costs along the path)
Transport directly over IP, protocol 89 (not TCP, not UDP)
Multicast address for all OSPF routers 224.0.0.5
Multicast address for the DR and BDR 224.0.0.6
Routing table code O (and O*E2 for a received default route)

Areas. OSPF can split a network into areas to keep the LSDB small. For the CCNA you work with single-area OSPF: every interface is in area 0, the backbone. That's the setup throughout this guide.

The five OSPF packet types

swipe

Packet Purpose
Hello discovers neighbors and keeps them alive
DBD (Database Description) a summary of the LSDB, sent during synchronization
LSR (Link-State Request) "send me this LSA, I don't have it"
LSU (Link-State Update) carries the requested LSAs or a new change
LSAck acknowledges an LSU

Router ID

Every OSPF router has a router ID (RID): a 32-bit number written like an IPv4 address. It doesn't have to be a real address on the router, but it must be unique within the area. It identifies the router in the neighbor table and in LSAs, and it breaks ties in the DR election.

A router picks its RID in this order:

  1. the value set with router-id (the recommended approach);
  2. otherwise, the highest IPv4 address on an up loopback interface;
  3. otherwise, the highest IPv4 address on an up physical interface.

The interface in steps 2 and 3 doesn't need to be running OSPF. It only has to be up.

The trap: if you change the RID on a router that's already running OSPF, the new value doesn't take effect right away. IOS tells you so and waits for you to restart the process:

R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
% OSPF: Reload or use "clear ip ospf process" command, for this to take effect
R1(config-router)# end
R1# clear ip ospf process
Reset ALL OSPF processes? [no]: yes

clear ip ospf process drops every adjacency on the router for a few seconds, so in production save it for a maintenance window.

Neighbors and adjacency states

Routers send Hellos to 224.0.0.5, by default every 10 seconds on Ethernet. If a router hears nothing from a neighbor for 40 seconds (the dead interval), it declares the neighbor down.

For two routers to become neighbors, several fields in their Hellos must match:

swipe

Must match Notes
Area ID both interfaces in the same area
Hello and dead intervals 10 and 40 seconds by default on Ethernet and serial links
Subnet and mask checked on broadcast networks, ignored on point-to-point
Authentication if configured (outside the CCNA scope)
Area type (stub flag) doesn't affect you in a single area

On top of that, the router IDs must be different, and the interface MTU must match (checked a bit later, in the DBD packets).

Getting to a full adjacency takes seven states:

swipe

State What's happening
Down no Hello received from the neighbor
Init I've received a Hello from the neighbor, but it doesn't list me yet
2-Way each router sees itself in the other's Hello; communication is two-way. The DR and BDR are elected here
ExStart the neighbors decide who leads the exchange (master/slave; the higher RID wins)
Exchange they send each other LSDB summaries in DBD packets
Loading they request missing LSAs with LSRs and receive them in LSUs
Full the LSDBs are identical; the adjacency is complete

The state you want is FULL. The one normal exception is 2-Way between two DROTHER routers on the same multi-access segment (see the next section).

DR and BDR on multi-access networks

If every router on a busy switch formed a full adjacency with every other one, you'd have n(n−1)/2 adjacencies: 10 for five routers, each with its own synchronization traffic.

OSPF avoids this with a DR (Designated Router) and a BDR (Backup DR) on each multi-access segment:

  • every router goes FULL only with the DR and the BDR;
  • the remaining routers, called DROTHERs, stay at 2-Way with each other;
  • a DROTHER sends changes to 224.0.0.6 (DR and BDR), and the DR floods them to everyone at 224.0.0.5;
  • if the DR fails, the BDR takes over and a new BDR is elected.

With five routers, that's 7 full adjacencies instead of 10, and the savings grow with every router you add.

Election rules

  1. The highest OSPF interface priority wins (0–255, default 1).
  2. On a tie, the highest router ID wins.
  3. Priority 0 means the router can never become DR or BDR.
  4. The election is not preemptive. A higher-priority router that boots later doesn't take over from the current DR.

The election happens per segment, not per router: the same router can be the DR on one interface and a DROTHER on another. When an interface comes up, the router waits for a period equal to the dead interval (the wait timer, 40 seconds) to find out whether a DR already exists.

Applied to our topology

With default priorities, every router on 10.0.0.0/24 has priority 1, so the RID decides: if they all start together, R3 (3.3.3.3) becomes the DR and R2 (2.2.2.2) the BDR.

We want R1, the least loaded router, to be the DR. We raise its priority on the interface facing the segment:

R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# ip ospf priority 200

Because the election isn't preemptive, nothing changes until you reset OSPF on the routers on that segment at about the same time (clear ip ospf process). After the reset, R1 becomes the DR (priority 200) and R3 becomes the BDR (same priority as R2, but a higher RID).

A router that should never become DR or BDR gets ip ospf priority 0 on its interface.

Network types: broadcast and point-to-point

OSPF behaves differently depending on the interface's network type:

swipe

Type Where you see it DR/BDR Default Hello / Dead
Broadcast Ethernet (default) yes 10 / 40 s
Point-to-point serial with HDLC or PPP (default), Ethernet when set manually no 10 / 40 s

The R3–R4 link has only two routers, but as Ethernet it defaults to broadcast: a pointless DR/BDR election and a 40-second wait at startup. Make it point-to-point at both ends:

R3(config)# interface GigabitEthernet0/0/1
R3(config-if)# ip ospf network point-to-point

R4(config)# interface GigabitEthernet0/0/0
R4(config-if)# ip ospf network point-to-point

Point-to-point links have no DR or BDR, neighbors go on to FULL with no election and no wait timer, and the neighbor table shows the state as FULL/ -.

Don't leave one end broadcast and the other point-to-point. The timers are the same (10/40), so the adjacency can still come up, but the two routers describe the link differently in the LSDB, and routes across it don't make it into the routing table.

Cost and reference bandwidth

The OSPF metric is cost. An interface's cost is:

cost = reference bandwidth / interface bandwidth

The result is rounded down, and the minimum cost is 1. The default reference bandwidth is 100 Mbps. The cost of a path is the sum of the outgoing interface costs along the way, including the interface on the destination network.

swipe

Interface Bandwidth Cost, default reference (100 Mbps) Cost, reference 10000 Mbps
Serial T1 1.544 Mbps 64 6476
Ethernet 10 Mbps 10 1000
FastEthernet 100 Mbps 1 100
GigabitEthernet 1 Gbps 1 10
10 GigabitEthernet 10 Gbps 1 1

The table shows the problem: with the default reference, a 100 Mbps link and a 10 Gbps link cost the same. On modern networks you raise the reference, on every router (the value is in Mbps):

R1(config)# router ospf 1
R1(config-router)# auto-cost reference-bandwidth 10000
% OSPF: Reference bandwidth is changed.
        Please ensure reference bandwidth is consistent across all routers.

A router with a different reference calculates costs on a different scale, and path selection stops making sense.

Two other ways to influence cost, both per interface:

  • ip ospf cost 50 sets the cost directly (it overrides the calculation);
  • bandwidth 50000 (in kbps) changes the value used in the calculation. It doesn't change the interface's real speed, only the number routing protocols work with.

An example from our topology, with the default reference (all interfaces are Gigabit, so cost 1 each): from R1 to 192.168.40.0/24 the packet leaves R1's Gi0/0/0 (1), R3's Gi0/0/1 (1) and R4's Gi0/0/1 (1). The total cost is 3. With a 10000 reference, it would be 30.

When several paths have the same cost, OSPF installs all of them and load-balances across them (up to 4 paths by default).

Configuring OSPF

Configuration has two parts: start the OSPF process, then tell it which interfaces to run on. For the second part you have two options.

Option 1: the network command with a wildcard (on R1)

R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.0.0.0 0.0.0.255 area 0
R1(config-router)# network 192.168.10.0 0.0.0.255 area 0
R1(config-router)# passive-interface GigabitEthernet0/0/1

Things to remember:

  • The 1 in router ospf 1 is the process ID, and it only matters locally (1–65535). Neighbors can use different process IDs and still form an adjacency. What has to match is the area.
  • The network command doesn't advertise a network directly. It means "enable OSPF on any interface whose address falls in this range". The network that gets advertised is then the interface's own subnet, with its own mask.
  • The second number is a wildcard mask, the inverse of the subnet mask: subtract each mask octet from 255. A /24 becomes 0.0.0.255, a /30 becomes 0.0.0.3, and a /20 becomes 0.0.15.255.

You can be even more precise and use the interface address with a 0.0.0.0 wildcard. That's how R4 is configured:

R4(config)# router ospf 1
R4(config-router)# router-id 4.4.4.4
R4(config-router)# network 10.0.34.2 0.0.0.0 area 0
R4(config-router)# network 192.168.40.1 0.0.0.0 area 0
R4(config-router)# passive-interface GigabitEthernet0/0/1

A 0.0.0.0 wildcard matches a single address, so it enables OSPF on exactly the interface that owns it. If wildcards trip you up, check them with the subnet calculator or the binary converter.

Option 2: ip ospf on the interface (on R2)

R2(config)# router ospf 1
R2(config-router)# router-id 2.2.2.2
R2(config-router)# passive-interface GigabitEthernet0/0/1
R2(config-router)# exit
R2(config)# interface GigabitEthernet0/0/0
R2(config-if)# ip ospf 1 area 0
R2(config-if)# exit
R2(config)# interface GigabitEthernet0/0/1
R2(config-if)# ip ospf 1 area 0

No wildcards to work out here: the interface you type the command on joins OSPF in the given area. It's harder to get wrong and easier to read in show running-config. If an interface is matched by both a network statement and ip ospf ... area, the interface configuration wins.

Passive interfaces

A LAN full of PCs has no other router on it, so Hellos are pointless there. Worse, a rogue device on that LAN could become a neighbor and inject bogus routes.

passive-interface handles both: it stops Hellos on the interface (so no neighbor can form there), but the interface's network is still advertised. On R1, 192.168.10.0/24 still reaches the other routers even though Gi0/0/1 is passive.

On a router with many LANs it's easier the other way round: everything passive, then re-enable only the interfaces facing other routers.

R3(config)# router ospf 1
R3(config-router)# passive-interface default
R3(config-router)# no passive-interface GigabitEthernet0/0/0
R3(config-router)# no passive-interface GigabitEthernet0/0/1

Careful: put passive-interface on an interface that faces a neighboring router and that adjacency goes down.

Propagating a default route (on R3)

R3 is the only router with a way out to the internet. Give it a static default route toward the ISP and tell OSPF to advertise it:

R3(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
R3(config)# router ospf 1
R3(config-router)# router-id 3.3.3.3
R3(config-router)# network 10.0.0.0 0.0.0.255 area 0
R3(config-router)# network 10.0.34.0 0.0.0.3 area 0
R3(config-router)# default-information originate

What you need to know:

  • default-information originate advertises the default route only if R3 has one in its routing table. With default-information originate always it advertises it regardless, but then the other routers may send traffic to an R3 that has nowhere to forward it.
  • The 203.0.113.0/30 network is not added to OSPF. You don't want to send Hellos toward the provider.
  • On the other routers the route shows up as O*E2 0.0.0.0/0 [110/1]: E2 means an external type 2 route, whose metric of 1 doesn't grow along the path. R3 becomes an ASBR (a router at the boundary with a network outside OSPF).

Troubleshooting common OSPF problems

Work bottom-up: the interfaces are up/up and the neighbor answers a ping; OSPF runs on the right interface and in the right area (show ip ospf interface); the neighbor shows up as FULL (show ip ospf neighbor); the routes reach the table (show ip route ospf).

swipe

Symptom Likely cause How to check and fix
Neighbor never appears different areas at the two ends show ip ospf interface on both → same area in network or ip ospf ... area
Neighbor never appears mismatched hello or dead interval show ip ospf interface (Timer intervals line) → same values, or no ip ospf hello-interval and no ip ospf dead-interval
Neighbor never appears addresses in different subnets, or a different mask on a broadcast segment show ip interface brief, show running-config interface → fix the address or mask
Neighbor never appears the interface is passive show ip protocols (Passive Interface(s)) → no passive-interface
Neighbor never appears the network statement doesn't match the interface (wrong wildcard) show ip ospf interface brief (interface missing) → fix the network statement
Neighbors stuck in EXSTART or EXCHANGE MTU mismatch between the two interfaces show interfaces (MTU) → same ip mtu at both ends
No adjacency, duplicate router ID messages (%OSPF-4-DUP_RTRID_NBR) two neighbors with the same router ID show ip ospf or show ip protocols → unique router-id, then clear ip ospf process
Every neighbor on a segment in 2WAY, no DR all routers have priority 0 show ip ospf interface → at least one router with priority above 0
Neighbors are FULL, but routes across the link are missing one end broadcast, the other point-to-point show ip ospf interface (Network Type) → same type at both ends
Default route doesn't reach the other routers missing static route on the edge router, or missing default-information originate show ip route on R3 → ip route 0.0.0.0 0.0.0.0 ... and default-information originate

If you can't change the MTU at one end, ip ospf mtu-ignore on the interface skips the check; it's a workaround, and the clean fix is matching MTUs. A duplicate RID between routers that aren't direct neighbors shows up differently: routes that keep appearing and disappearing.

A note on OSPFv3

IPv6 uses OSPFv3, with the same logic (neighbors, DR/BDR, cost, area 0), configured per interface with no network statements:

R1(config)# ipv6 unicast-routing
R1(config)# ipv6 router ospf 1
R1(config-rtr)# router-id 1.1.1.1
R1(config-rtr)# exit
R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# ipv6 ospf 1 area 0

The RID is still 32 bits; on a router with no IPv4 address at all you must set it manually, or the process won't start. Neighbors talk over link-local addresses (see the IPv6 addresses guide). OSPFv3 is named explicitly in the next version of the exam, covered in our article on CCNA v2.0 in 2027.

Exercises

  1. Which network command puts every interface in 172.16.32.0/20 into area 0?
  2. Four routers share a switch and boot at the same time. RA: priority 1, RID 4.4.4.4. RB: priority 10, RID 1.1.1.1. RC: priority 1, RID 9.9.9.9. RD: priority 0, RID 99.99.99.99. Which router is the DR, which is the BDR, and what state are RA and RD in with each other?
  3. Every router has auto-cost reference-bandwidth 1000. A packet leaves R1 on a FastEthernet interface, then leaves R2 on a GigabitEthernet interface, and the destination network is attached to R3, also on a GigabitEthernet interface. What cost does R1's routing table show for the route?
  4. On R2, show ip ospf neighbor shows nothing. On R1, show ip ospf interface shows "Hello 10, Dead 40"; on R2 it shows "Hello 5, Dead 20". What happened, and how do you fix it on R2?
  5. A router has no router-id. It has Loopback0 at 10.255.255.1 and Gi0/0/0 at 192.168.50.1, both up. Which RID does it choose? What happens if you then add router-id 7.7.7.7?
Answers

1. A /20 mask is 255.255.240.0, so the wildcard is 0.0.15.255:

R1(config-router)# network 172.16.32.0 0.0.15.255 area 0

2. RB is the DR because it has the highest priority (10). That leaves RA and RC for BDR, both at priority 1, so the higher RID wins: RC (9.9.9.9). RD has priority 0, so it's out of the election despite having the highest RID. RA and RD are both DROTHERs, so they stay in 2WAY with each other.

3. With a 1000 Mbps reference: FastEthernet = 1000/100 = 10, GigabitEthernet = 1000/1000 = 1. The cost is 10 + 1 + 1 = 12. You add up the outgoing interfaces along the path, including R3's interface on the destination network.

4. Someone changed R2's hello interval to 5 seconds, and the dead interval adjusted itself to 20. The timers must match, so R1 and R2 ignore each other's Hellos. On R2's interface:

R2(config-if)# no ip ospf hello-interval
R2(config-if)# no ip ospf dead-interval

5. It picks 10.255.255.1, the loopback address. Loopbacks beat physical interfaces even when their address is lower. After router-id 7.7.7.7, IOS prints a message saying the change takes effect after a reload or clear ip ospf process. Until then, the RID stays 10.255.255.1.

The fastest way to learn OSPF

  • Build the topology from this guide in a simulator and watch the states with show ip ospf neighbor as you bring interfaces up.
  • Break one thing at a time on purpose (area, hello, MTU, passive interface) and fix it using only show commands.
  • Practice on paper DR/BDR elections and cost calculations until you can answer in seconds.

Frequently asked questions

What is OSPF?

A link-state dynamic routing protocol. Every router learns the topology of the whole area, stores it in a database (the LSDB) and computes the shortest path to each network on its own with the SPF (Dijkstra) algorithm. It's an open standard, so it works between vendors.

How does OSPF choose its router ID?

In this order: the value set with router-id; if there isn't one, the highest IPv4 address on an up loopback interface; if there's no loopback, the highest IPv4 address on an up physical interface. A new RID only takes effect after clear ip ospf process or a reload.

How are the DR and BDR elected?

On each multi-access segment, the highest OSPF interface priority wins (default 1, range 0 to 255), and on a tie the highest RID wins. Priority 0 takes a router out of the election. The election isn't preemptive: a better router that shows up later doesn't replace the current DR.

What is the administrative distance of OSPF?

110. That's higher than static routes (1) and internal EIGRP (90), so for the same network a router prefers a static or EIGRP route over an OSPF one.

Why are some OSPF neighbors stuck in 2WAY?

They usually aren't stuck. On a multi-access segment, routers that are neither DR nor BDR (DROTHERs) stop at 2-Way with each other. That's normal: they only go FULL with the DR and the BDR.

Why change the OSPF reference bandwidth?

Cost is the reference bandwidth divided by the interface bandwidth. The default reference is 100 Mbps, so FastEthernet, GigabitEthernet and 10 GigabitEthernet all get cost 1 and OSPF can't tell them apart. auto-cost reference-bandwidth raises the value; set it the same on every router.
