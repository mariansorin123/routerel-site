DHCP on Cisco: Server, Relay and Troubleshooting

The Routerel team· Updated: November 9, 2026· 16 min read

Without DHCP, every laptop, phone and printer on a network would need its address typed in by hand. With DHCP, a device plugs in, asks for an address, and a moment later it has everything it needs to reach the internet.

This guide covers what a client actually gets from DHCP, how the DORA exchange works at the broadcast/unicast level, how leases are renewed, and how to configure a Cisco router as a DHCP server, a relay agent and a client. You'll also see the show commands that matter, a method for tracking down 169.254.x.x addresses, and what DHCP snooping is for. Exercises with answers are at the end.

In the Networking Academy CCNA v8 courses, DHCPv4 is module 8 of CCNA 2 · IEN, SLAAC and DHCPv6 are module 9, and DHCP snooping shows up in module 11 (access and Layer 2 security).

What DHCP gives a client

DHCP (Dynamic Host Configuration Protocol) is an application-layer protocol that runs over UDP: the server listens on port 67 and the client on port 68. It grew out of the older BOOTP protocol, which is why ACLs show port 67 as bootps and port 68 as bootpc.

A DHCP server typically hands the client:

swipe

What the client gets DHCP option Cisco pool command
IPv4 address and mask yiaddr field + option 1 network
Default gateway option 3 default-router
DNS servers option 6 dns-server
Domain name option 15 domain-name
Lease time option 51 lease

The key word is lease. The client doesn't own the address; it borrows it for a period and has to renew it. That way, addresses used by devices that leave the network flow back into the pool on their own.

A Cisco router makes a perfectly good DHCP server for a branch office or a small site. In larger networks the server is usually Windows Server, a Linux box or a dedicated IP address management system, and the routers and Layer 3 switches only relay. The exam expects you to know both roles.

The DORA process, step by step

The client starts with no IP address. All it knows is its own MAC address. That's the interesting part: it has to talk to a server it doesn't know, without an address of its own.

swipe

Step Message Source IP → destination IP Ports Delivery
1 Discover (client looks for servers) 0.0.0.0 → 255.255.255.255 68 → 67 broadcast (destination MAC ff:ff:ff:ff:ff:ff)
2 Offer (server proposes an address) server → offered address 67 → 68 Layer 2 unicast to the client's MAC
3 Request (client asks for the chosen address) 0.0.0.0 → 255.255.255.255 68 → 67 broadcast
4 Acknowledgment (server confirms) server → offered address 67 → 68 Layer 2 unicast to the client's MAC

Details that come up a lot in exam questions:

  • Why is the Request still a broadcast? Several servers may answer the same Discover. The client picks one offer (usually the first) and announces its choice to all of them at once: the Request carries the chosen server's identifier (option 54). The other servers see that their offer lost and keep their addresses.
  • Offer and Ack aren't always unicast. If the client set the broadcast flag in its Discover (some operating systems can't accept unicast before they have an address), the server broadcasts its replies. For the CCNA, remember the basic version: Discover and Request are broadcast, Offer and Ack go to the client's MAC.
  • Before offering an address, the Cisco IOS server pings it twice by default. If anything answers, the address is flagged as a conflict and not offered.
  • After the Ack, the client may also check with ARP that nobody else uses the address. If it does find a duplicate, it sends a DHCPDECLINE and starts over.

Other messages worth knowing: DHCPNAK (the server rejects a request, for example when the client asks for an address from a subnet it has moved away from), DHCPRELEASE (the client gives the address back, as with ipconfig /release) and DHCPINFORM (the client already has an address and only wants the other settings).

Leases and renewal (T1 and T2)

Every address comes with a lease time, and the client doesn't wait for it to run out:

  • T1, at 50% of the lease: the client sends a unicast Request straight to the server that gave it the address. If that server answers with an Ack, the lease starts over and the client keeps its address.
  • T2, at 87.5% of the lease: if the original server stayed silent, the client broadcasts a Request to any server that can help (rebinding).
  • At expiry: with no answer at all, the client drops the address and starts again with a Discover.

With the Cisco default of one day (24 hours), T1 comes after 12 hours and T2 after 21 hours.

On the Cisco IOS server you set the lease inside the pool with lease days [hours [minutes]] or lease infinite. lease 7 is seven days; lease 0 8 is eight hours. A short lease recycles addresses quickly on a guest network; a long one cuts renewal traffic in an office where the same machines show up every day.

The topology used in this guide

   LAN 10 hosts                                          LAN 20 hosts
   192.168.10.0/24                                       192.168.20.0/24
   internal DNS 192.168.10.10                                  |
         |                                                     |

  • R1 is the DHCP server for both LANs.
  • R2 has no server of its own; it relays LAN 20 requests to R1.
  • R1 also gets the address on its ISP-facing interface through DHCP.

Configuring the router as a DHCP server

Step 1: exclude the static addresses

Gateways, servers, printers and anything else with a fixed address must stay out of the pool. Exclusions are configured in global configuration mode, not inside the pool:

R1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.20
R1(config)# ip dhcp excluded-address 192.168.20.1 192.168.20.10

The syntax is ip dhcp excluded-address low-address [high-address]. With a single address you exclude just that one. Add the exclusions before you create the pool; otherwise the router may hand a PC an address you had reserved for a server or a printer.

Step 2: build the pool

R1(config)# ip dhcp pool LAN10
R1(dhcp-config)# network 192.168.10.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.10.1
R1(dhcp-config)# dns-server 192.168.10.10
R1(dhcp-config)# domain-name example.com
R1(dhcp-config)# lease 2
R1(dhcp-config)# exit

What each line does:

  • ip dhcp pool LAN10 creates the pool and enters dhcp-config mode. You pick the name.
  • network sets the subnet the addresses come from. Prefix notation works too: network 192.168.10.0 /24.
  • default-router is the gateway the clients will use. You can list up to 8 addresses, in order of preference.
  • dns-server also takes up to 8 addresses.
  • domain-name is the DNS suffix appended to short names (srv1 becomes srv1.example.com).
  • lease 2 means two days. Leave it out and the lease is one day.

How does the router pick the right pool? For a directly connected client, it matches the address of the interface the Discover arrived on: a Discover on G0/0/0 (192.168.10.1) matches pool LAN10. If no pool's network matches the interface, the router simply doesn't answer.

A pool for the subnet behind the relay

R1 also serves LAN 20, even though it isn't directly connected to it:

R1(config)# ip dhcp pool LAN20
R1(dhcp-config)# network 192.168.20.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.20.1
R1(dhcp-config)# dns-server 192.168.10.10
R1(dhcp-config)# domain-name example.com
R1(dhcp-config)# exit
R1(config)# ip route 192.168.20.0 255.255.255.0 10.1.1.2

The last line is the one people forget. R1 sends its replies to the relay's address in LAN 20 (192.168.20.1), so it needs a route to 192.168.20.0/24. In a real network that route might come from OSPF; what matters is that it exists.

The DHCP service is on by default in IOS. If someone typed no service dhcp, the router stops acting as both server and relay. Turn it back on with service dhcp.

DHCP relay with ip helper-address

Routers don't forward broadcasts. A Discover from a PC in LAN 20 stops at R2 and never reaches R1. Without some help, you'd need a DHCP server in every subnet and every VLAN.

The fix is a DHCP relay agent: on the router interface facing the clients, you point to the server.

R2(config)# interface GigabitEthernet0/0/0
R2(config-if)# ip address 192.168.20.1 255.255.255.0
R2(config-if)# ip helper-address 10.1.1.1
R2(config-if)# no shutdown

What happens to a Discover from LAN 20:

  1. The PC broadcasts a Discover. R2 receives it on G0/0/0.
  2. R2 fills in the giaddr (gateway IP address) field with the address of the interface the request came in on: 192.168.20.1.
  3. R2 sends the message as a unicast to 10.1.1.1 on UDP port 67.
  4. R1 sees giaddr = 192.168.20.1 and picks pool LAN20, the one whose network contains that address.
  5. R1 replies by unicast to 192.168.20.1 (hence the route to LAN 20).
  6. R2 hands the reply to the client in LAN 20 on UDP port 68.

The classic mistake is putting the helper on the interface that faces the server (G0/0/1 on R2). The command belongs where the clients' broadcasts arrive.

Relaying across VLANs

Each VLAN is a separate subnet with its own broadcast domain. If the DHCP server sits in a server VLAN, you add ip helper-address to every gateway interface: each subinterface with router-on-a-stick, or each SVI on a Layer 3 switch.

D1(config)# interface vlan 30
D1(config-if)# ip address 192.168.30.1 255.255.255.0
D1(config-if)# ip helper-address 192.168.99.50
D1(config-if)# exit
D1(config)# interface vlan 40
D1(config-if)# ip address 192.168.40.1 255.255.255.0
D1(config-if)# ip helper-address 192.168.99.50

If VLANs and trunks are still fuzzy, read the VLANs and trunks guide first.

What else ip helper-address forwards

The command isn't only for DHCP. By default the router also forwards UDP broadcasts for a handful of other services to the helper address, such as DNS (53), TFTP (69), TACACS (49), Time (37) and NetBIOS (137, 138). You can change the list with ip forward-protocol udp port or no ip forward-protocol udp port.

The router as a DHCP client

Plenty of small-business internet connections get their address from the provider through DHCP. On the router, the ISP-facing interface becomes a client:

R1(config)# interface GigabitEthernet0/0/2
R1(config-if)# ip address dhcp
R1(config-if)# no shutdown

To verify:

R1# show ip interface brief | include 0/0/2
GigabitEthernet0/0/2   203.0.113.45    YES DHCP   up                    up

R1# show ip route static | include 0.0.0.0
S*    0.0.0.0/0 [254/0] via 203.0.113.1

The Method column says DHCP. If the provider's server also sends a gateway (option 3), IOS installs a static default route on its own, with an administrative distance of 254. The high value is deliberate: any default route you configure yourself wins. For lease details (server, time left), use show dhcp lease.

For an Ethernet client, the client ID is 01 (the hardware type) followed by the MAC address. The LAN 20 client shows "Unknown" as its interface because it came in through the relay. Its lease also ends sooner, since pool LAN20 keeps the default one-day lease.

"Current index" is the next address the server will try. The third PC got .24, not .23, because .23 is in conflict, as the next output shows.

R1# show ip dhcp conflict
IP address        Detection method   Detection time          VRF
192.168.10.23     Ping               Nov 09 2026 09:21 AM

A conflicting address stays out of the pool until you release it. Find the device with the hand-typed address, fix it, then clear the entry with clear ip dhcp conflict 192.168.10.23 (or clear ip dhcp conflict * for all of them). Similarly, clear ip dhcp binding * wipes every lease, which is handy in a lab.

debug ip dhcp server events, carefully

R1# debug ip dhcp server events
R1# undebug all

debug shows you live what the server is doing: which request arrived, which address it offered, which lease it confirmed. In a lab it's great. On a production router, though, debug costs CPU and can flood you with thousands of lines on a busy server. Use it only when you know why, keep it short, and stop it with undebug all (or no debug all). Over SSH you'll only see the messages after terminal monitor. For even more detail there's debug ip dhcp server packet.

On the client side, on a Windows PC, ipconfig /all shows the address, gateway, DNS servers and DHCP server, and ipconfig /release followed by ipconfig /renew runs DORA again.

Troubleshooting: from 169.254 to the root cause

When a Windows client (and many other systems) gets no DHCP answer at all, it assigns itself an address from 169.254.0.0/16, known as APIPA or an IPv4 link-local address. It can only talk to neighbors on the same link, with no gateway. If you see 169.254.x.x, one thing is certain: no Offer reached the client. Your job is to find where it stopped.

Work from the client toward the server:

  1. Client: is the cable plugged in? Does ipconfig /all show 169.254? Try ipconfig /renew.
  2. Switch: is the port in the right VLAN (show vlan brief)? Does the trunk carry that VLAN (show interfaces trunk)?
  3. Client's gateway: does the VLAN's interface or SVI have ip helper-address? Is the address in it correct?
  4. Path: can the gateway ping the server? Does the server have a route back to the client's subnet?
  5. Server: is there a pool whose network contains the giaddr? Are there free addresses left? What do show ip dhcp server statistics and, carefully, debug ip dhcp server events say?

swipe

Symptom Likely cause How to check and fix
Every client in one VLAN has 169.254.x.x missing ip helper-address on the SVI or subinterface show running-config interface vlan 20 → add the helper
Clients behind the relay get 169.254, local ones work the server has no route to the client subnet show ip route on the server → static route or OSPF
A single PC has 169.254 port in the wrong VLAN, port down, cable show vlan brief, show interfaces status
New clients get nothing, existing ones work pool exhausted show ip dhcp pool (leased = total) → bigger pool, shorter lease
Clients get an address but can't leave the subnet wrong or missing default-router ipconfig /all on the PC, show running-config | section dhcp
Clients work by IP but not by name wrong or missing dns-server ipconfig /all, nslookup
Some clients get odd gateways a rogue DHCP server on the network ipconfig /all (check "DHCP Server") → DHCP snooping
Conflict messages, addresses that "disappear" statically addressed devices inside the pool range show ip dhcp conflict → ip dhcp excluded-address
Everything broke after DHCP snooping was enabled uplink to the server not trusted, or the option 82 issue show ip dhcp snooping → ip dhcp snooping trust on the uplink
The router doesn't answer at all, even locally no service dhcp in the config, or an ACL blocking UDP 67 show running-config | include dhcp, show access-lists

DHCP snooping in brief

DHCP has no authentication. Anyone who plugs in a home router or starts a DHCP server on a laptop can answer Discovers faster than the real server. The typical attacks:

  • DHCP spoofing: a fake server gives clients a gateway or DNS server controlled by the attacker, who can then see their traffic (man-in-the-middle).
  • DHCP starvation: the attacker sends thousands of Discovers with made-up MAC addresses and drains the pool, so real clients get nothing. It's often the first step before spoofing.

DHCP snooping is the switch feature that deals with this. Ports become one of two kinds:

  • trusted: ports toward the legitimate DHCP server and the uplinks to the rest of the network. All DHCP messages are allowed.
  • untrusted: every other port (the default once snooping is on). Server messages (Offer, Ack, Nak) arriving here are dropped. Clients can still send Discovers and Requests, but they can't act as a server.
S1(config)# ip dhcp snooping
S1(config)# ip dhcp snooping vlan 10,20
S1(config)# interface GigabitEthernet0/1
S1(config-if)# description Uplink toward the DHCP server
S1(config-if)# ip dhcp snooping trust
S1(config-if)# exit
S1(config)# interface range FastEthernet0/1 - 24
S1(config-if-range)# ip dhcp snooping limit rate 10
  • Snooping must be enabled globally and per VLAN; ip dhcp snooping on its own does nothing useful.
  • limit rate 10 allows at most 10 DHCP packets per second on the port; above that the port goes err-disabled. Together with port security, it's a defense against starvation.
  • The switch builds a binding table (MAC, IP, VLAN, port) that Dynamic ARP Inspection and IP Source Guard rely on. You can see it with show ip dhcp snooping binding.

One lab trap: with snooping on, a Catalyst switch inserts option 82 into client requests by default. A Cisco IOS DHCP server that receives such a request with no giaddr drops it, and the clients end up with nothing. In a lab, the usual fix is no ip dhcp snooping information option on the switch.

IPv6 works differently

DHCPv4 doesn't hand out IPv6 addresses. In IPv6, routers send periodic Router Advertisements (RAs), and two flags in them tell the client what to do:

swipe

Method RA flags Where the address comes from Where DNS and other settings come from
SLAAC M = 0, O = 0 the client builds it from the RA prefix the RA (RDNSS option, if sent)
Stateless DHCPv6 M = 0, O = 1 SLAAC the DHCPv6 server
Stateful DHCPv6 M = 1 the DHCPv6 server the DHCPv6 server

What's different from DHCPv4:

  • The default gateway always comes from the RA (the router's link-local address), never from DHCPv6.
  • DHCPv6 uses UDP 546 (client) and 547 (server). IPv6 has no broadcast, so the client sends to the multicast address ff02::1:2.
  • On Cisco, the flags are set per interface with ipv6 nd other-config-flag (O) and ipv6 nd managed-config-flag (M). Relaying uses ipv6 dhcp relay destination instead of ip helper-address.

SLAAC, EUI-64 and the IPv6 address types are covered in the IPv6 addresses guide, and you can check addresses quickly with the IPv6 tool.

Exercises

  1. R1 has pool LAN10 with network 192.168.10.0 255.255.255.0, but you forgot ip dhcp excluded-address. The gateway is 192.168.10.1 and a printer uses the static address 192.168.10.5. What can go wrong, and which command is missing?
  2. A client gets an 8-hour lease at 08:00. When does it first try to renew, and who does it ask? When does it switch to broadcast?
  3. Clients in VLAN 30 (192.168.30.0/24, SVI gateway 192.168.30.1 on switch D1) must get addresses from the server at 10.10.10.5. Which command do you need, and on which interface?
  4. Configure a pool called GUESTS for 172.16.50.0/24: gateway 172.16.50.1, DNS 172.16.50.2, a 4-hour lease, with the first 10 addresses excluded.
  5. Right after you enable DHCP snooping on an access switch, every client gets 169.254.x.x. The server is a router connected to G0/1. What are the two likely causes?
  6. A router's G0/0/2 has ip address dhcp, and you add ip route 0.0.0.0 0.0.0.0 198.51.100.1. Which default route will the router use, and why?
Answers

1. The static addresses stay in the pool. The ping before each offer usually catches them and logs them in show ip dhcp conflict, but if the printer happens to be off at that moment, 192.168.10.5 can go to a PC, and the real conflict appears when the printer powers back on. The missing piece is ip dhcp excluded-address 192.168.10.1 192.168.10.20 (or any range that covers the static addresses), in global configuration mode.

2. T1 = 50% of 8 hours = 4 hours, so at 12:00 the client sends a unicast Request to the server that gave it the address. T2 = 87.5% of 8 hours = 7 hours, so at 15:00, if it still has no answer, it broadcasts a Request to any server.

3. On the VLAN 30 SVI, where the clients' broadcasts arrive:

D1(config)# interface vlan 30
D1(config-if)# ip helper-address 10.10.10.5

The server also needs a pool for 192.168.30.0/24 and a route back to that subnet.

4.

R1(config)# ip dhcp excluded-address 172.16.50.1 172.16.50.10
R1(config)# ip dhcp pool GUESTS
R1(dhcp-config)# network 172.16.50.0 255.255.255.0
R1(dhcp-config)# default-router 172.16.50.1
R1(dhcp-config)# dns-server 172.16.50.2
R1(dhcp-config)# lease 0 4

5. First, G0/1 toward the server isn't set to ip dhcp snooping trust, so the switch drops the Offers. Second, the switch inserts option 82 and the Cisco IOS server drops requests that carry option 82 with no giaddr. Fix it with ip dhcp snooping trust on G0/1 and, if needed, no ip dhcp snooping information option.

6. Your configured route via 198.51.100.1. A static route has an administrative distance of 1, while the DHCP-learned default route has 254. The lower distance wins.

How to learn DHCP fastest

  • Build the topology from this guide in Packet Tracer: local server first, then the relay, then break something on purpose (remove the helper, the route, the exclusions) and find the fault using only show commands.
  • Draw DORA on paper with source and destination IPs, ports, and broadcast vs unicast. If you can rebuild that table from memory, you've covered most of the exam questions.
  • Place DHCP in the layer models: it's an application protocol over UDP that serves Layer 3. See OSI vs TCP/IP.
  • Drill the basic commands from the Cisco IOS commands cheat sheet and the range math from the subnetting guide.

Frequently asked questions

What is DHCP?

The protocol that lets a device automatically get its IPv4 address, subnet mask, default gateway, DNS servers and other settings from a server, for a limited time called a lease.

Which ports does DHCP use?

DHCPv4 runs over UDP: the server listens on port 67 and the client on port 68. DHCPv6 uses different ports: 547 for the server and 546 for the client.

What does DORA stand for?

The four messages a client uses to get an address: Discover (the client looks for servers), Offer (a server proposes an address), Request (the client asks for the address it chose) and Acknowledgment (the server confirms).

Why do I need ip helper-address?

Discovers are broadcasts, and routers don't forward broadcasts. When the DHCP server is in another subnet or VLAN, ip helper-address on the interface facing the clients turns the broadcast into a unicast sent to the server.

Why does my PC get a 169.254.x.x address?

A 169.254.x.x address (APIPA) means the client got no answer from any DHCP server. Common causes: a missing helper, a wrong VLAN, an exhausted pool, a missing route back to the client subnet, or DHCP snooping dropping the replies.

What is the default lease time on a Cisco router?

One day. You change it in the pool with lease, for example lease 7 for seven days or lease 0 8 for eight hours.

What does DHCP snooping do?

It only accepts DHCP server messages (Offer, Ack) on ports marked as trusted, so a rogue server plugged into a user port can no longer hand out fake addresses and gateways. For where DHCP fits in the exam, see our guide to CCNA.
